# 质量修复与分析扩展核验

核验日期：2026-09-14。基线为提交 `31040b5`，以当前本地文件为准。开始时 Notebook 有运行次数和输出改动，未发现源代码差异；当前文件和这些运行输出先备份到被 Git 忽略的本地目录，再进行修复。

## 本轮实际检查

- **真实样本：** 从现有数据库及 WAL 创建稳定快照，复制前后哈希一致。以只读方式复跑新版下游分析。原数据库、WAL 和验证快照的文件哈希在执行前后均未改变，`sample_events` 未被重建或修改。
- **质量规则：** 本次规范化记录数为 0，缺失 user/item/category ID、非法或缺失行为、不可解析时间戳均为 0。检查覆盖全部 994,112 条样本，包括有效时间窗外记录；不代表对未入样本的原 CSV 进行了全量质量认证。
- **Notebook：** 30 个代码单元从头执行，无错误，保存表格和两张内嵌图。已有数据库只读打开，派生表均为临时表。独立核心查询使用规范化字段；新增查询与终端共用扩展 SQL。
- **结果一致性：** Notebook 和终端导出的 13 份聚合 CSV 数值一致；与原有 10 份 CSV 的旧字段对比也一致，浮点容差为 `1e-12`。新字段和新表来自当前查询。
- **图表：** 检查新增样本活跃占比与加购路径图，坐标、比例、分子分母和标签与 CSV 一致。
- **输入保护：** 本轮没有重复扫描或复制几 GB 的原 CSV；只在 Notebook 开头读取少量行做字段检查。抽样入口未改动，以临时合成 CSV 验证 VARCHAR ID、用户 hash 选择、原行为值和重复记录保留，并验证拒绝覆盖已有数据库。

## 7 项合成回归

全部使用独立临时目录和数据库，不读取真实原始数据或原库。运行：

```bash
cd projects/taobao-user-behavior
python -m unittest discover -s tests -v
```

| 测试 | 实际覆盖 |
|---|---|
| 规范化、重复和 Notebook 一致性 | `" buy "` 计为购买，原值保留；重复购买记录按行保留而购买用户去重；SQL 与 Notebook 的核心汇总一致；源库字节不变 |
| 非法行为失败及旧输出保护 | unknown、BUY、空串、NULL 均失败；只有非法行为的用户不会进入正式活跃分母；SQL 不创建正式事件表，Notebook 关闭连接并抛错，CLI 非零退出且报告计数；旧输出文件哈希不变 |
| 缺失 ID 和不可解析时间戳 | 三类关键 ID 缺失／空白、非法、缺失和超出可解析范围的时间戳均失败；有效时间窗外的问题记录也不能绕过全样本门槛；SQL 和 Notebook 一致 |
| 绘图失败保护 | 聚合已成功但绘图失败时，旧成功 CSV 和图片仍保持原哈希 |
| after_only 历史窗口 | 只认 11 月 25—30 日；11 月 24 日、12 月 3 日不能用来定义“此前出现”；组别人数和购买人数核对 |
| 加购序列边界 | 首次加购、重复加购／购买、购买先于加购、同秒、严格后续、恰好 24h、超过 24h、错用户／错商品、非 12 月 2 日起点与窗口外购买；另在更短的合成观察窗口中验证截止点相等和观察不足排除 |
| 原 CSV 抽样 | 带前导零的 VARCHAR ID 参与原 hash 规则；重复记录和带空白原行为保留；原 CSV 字节不变，不覆盖已有数据库 |

## 既有复现证据与本轮边界

上一轮在 `31040b5` 发布前，已经从本机原 CSV 完整读取并重新抽样，与已有样本做双向 `EXCEPT ALL` 比较，差异为零（保留重复数量）。该记录是此前执行证据；本轮抽样代码未变，只复跑新版下游并用合成 CSV 验证入口，没有再次进行真实全 CSV 扫描。

使用既有 Python 3.12.14 / DuckDB 1.5.5 环境，核心依赖版本见 [requirements.txt](../requirements.txt)。未另建空白环境重装依赖，未重新从来源页下载数据，未验证其他 DuckDB 版本。原库可能被 IDE 占用，因此本轮使用稳定快照；日常运行原库仍应先关闭其他进程连接。

质量失败在正式指标和文件发布前退出；成功时先在临时目录完成全部 CSV 与图表再逐文件替换。不宣称跨多个文件的替换能抵御所有磁盘故障，也不把保留的上次成功输出误称为本次失败后的新结果。
