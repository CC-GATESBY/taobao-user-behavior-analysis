# 复现说明与验证记录

本页记录运行环境、质量规则和实际执行过的检查。完整启动命令见[案例 README](../README.md#运行与验证)，数据来源和字段见[数据说明](../data/README.md)。

## 执行环境

分析环境使用 Python **3.12.14**、DuckDB **1.5.5**、pandas **3.0.5**、NumPy **2.5.3**、Matplotlib **3.11.2**、ipykernel **7.3.0**。依赖约定见 [requirements.txt](../requirements.txt)。本地 Notebook 验证通过 nbclient 启动上述分析内核；Notebook 校验工具与分析内核分别运行。

固定 DuckDB 版本是为了保留用户 hash 抽样结果。五字段按 VARCHAR 读取，用户 ID 不作数值转换；`hash(user_id) % 100 = 0` 选择用户。时间统一为 Asia/Shanghai，窗口为 `[2017-11-25 00:00, 2017-12-04 00:00)`。

## 质量规则与文件保护

原始 `behavior_type` 保留，临时视图派生 `behavior_type_clean = TRIM(behavior_type)`。合法性与所有下游行为判断使用 clean 字段，合法值为 `pv/fav/cart/buy`，不自动转换大小写；另报因首尾空白发生规范化的记录数。

正式分析前检查整个 `sample_events`，包括窗外记录。缺失 user/item/category ID、规范化后非法或缺失行为、无法解析的时间戳任一非零，就报告各项数量并失败退出；空样本同样失败。一个问题行可能命中多项检查，不能把列计数直接相加当作问题行数。SQL 抛错，Notebook 关闭连接并抛错，终端返回非零状态，非法行为用户不会进入正式活跃分母。

有效窗外记录按既定窗口排除并披露。重复检查按五个原始字段进行，完全相同行继续保留；缺少唯一事件编号，不能据此判定应删除哪条记录。

脚本与 Notebook 只读打开已有数据库，派生表均为临时表。质量检查、汇总核对以及全部 CSV 和图表生成成功后，才逐文件替换输出目录中的同名文件，保留其他文件。质量或绘图失败不会覆盖旧成功结果；保留的旧文件也不代表失败运行产生了新结果。逐文件替换不提供跨多个文件的事务保证，不能承诺抵御所有断电或磁盘故障。

## 聚合结果的单位与边界

CSV 中的购买率、样本活跃占比和人数相对变化以比例保存，展示为百分比时乘 100；`weekday_comparison.csv` 的 `buyer_rate_change_pp` 已直接保存百分点。人数、行为记录和用户—商品对分别计数，不能互换分母。没有合格分母的比率以 NaN／CSV 空值表示，不写成 0%。

加购路径以目标日每个用户—商品对的首次加购为起点 `t0`，用 `EXISTS` 判断同用户、同商品在 `(t0, t0+24h]` 内是否有购买。观察窗口右端不包含，因此 `t0+24h` 必须严格早于 `2017-12-04 00:00`；观察不足的起点排除并披露。同秒购买另计，只有同秒而无严格后续购买时不算成功；另有后续购买时该对仍只计一次成功。
